## How it was read (Claude's reading of the dictation; inference)

- "build your own hardness": build your own harness, with tools of its own, because the work is called again and again.
- "one hour analysis and market is completed": run our analysis on each game not analysed yet, and mark it completed.
- "documenting where it's completed in Holland": document in the handler where each completed analysis is, so it can be found later.
- "publish them here self defects": publish them here as artifacts.
- "I have one big page HTML file": I want one big HTML file with several pages inside it as the summary report, linking to the web pages (each game's published art report).

## Decided without asking

- **One ledger of games** (`registry/games.json`), seeded with what the studio already had on record: 5 competitor GDD runs and the web research of 21 Nov in Intelligate HQ (17 games), and the Zeus vs Hades POP art run in Games-AI-art. 19 games; one (Zeus vs Hades POP) already analysed.
- **A sequel or version is its own game.** "Gates of Olympus 1000" is not "Gates of Olympus": its art differs.
- **The 20 leaders of a report with several lists**: 21 − rank points per list, summed (see `documents/method.md`). It is the handler's rule and is said to be so wherever the order is shown.
- **Only slot games** are leaders, as asked; crash, live and instant games a report ranks are recorded but not analysed.
- **The reports themselves are committed** (the PDF and its pages), as "everything should be in it". The repository is private.
- **The summary report is one self-contained HTML file** (`site/index.html`, pictures inside), published as a private artifact.
- Python only, with pdfplumber and Pillow; no build step.

## How it was checked

`python3 -I -m unittest discover tests` passes (matching, the leaders rule, a second unify of the same report, the Markdown reader). The site was built from the seeded ledger and looked at in a browser at desktop and phone width, in both themes.
